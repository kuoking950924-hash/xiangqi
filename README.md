# 棋局・殺伐 — Xiangqi

2D 等角視角中國象棋（Chinese Chess / Xiangqi）

一個純前端的中國象棋網頁遊戲，玩家對戰 AI。視覺採 45 度等角視角，戰場氛圍陰暗肅殺。

## 技術棧
- React 19 + Vite
- 純前端，無後端，不使用任何 3D 引擎（等角視覺效果純粹用 2D CSS 定位計算實現）

## 功能
- 完整中國象棋規則（帥/將、仕/士、相/象、馬、車、炮、兵/卒），包含蹩馬腿、塞象眼、炮的隔子吃子、飛將規則
- AI 對手：使用 minimax + alpha-beta 剪枝（搜尋深度 3 層），會判斷吃子價值、避免明顯送死走法
- 走子動畫：玩家與 AI 走子共用同一套動畫邏輯，確保每一步都有畫面回饋
- 將軍提示、勝負判斷（將死／困斃）

## Code Review 修正紀錄

### 嚴重問題
- **走子動畫邏輯反了**：動畫期間盤面仍是走子「前」的狀態，原程式碼卻去畫終點格上的棋子（那是被吃的棋子，或根本是空的）。導致一般移動完全沒有動畫、棋子直接瞬移。已改成從起點插值到終點。
- **AI 運算阻塞畫面**：`isInCheck` 原本要產生對方所有走法才能判斷，minimax 每個節點呼叫數十次，AI 一步要 ~800ms 同步運算，弱一點的機器會整頁卡死。已改為從將帥位置反向射線偵測，耗時降到 ~230-380ms。此改動附帶 `isInCheck.diff.test.mjs` 差異測試，用 200 盤隨機對局、近 24000 個盤面與暴力法逐一對照，確認結果完全一致。

### 其他修正
- 補上和局規則：三次重複局面判和、連續 60 回合無吃子判和（原本棋局可以無限循環）
- 移除被吃棋子的重複渲染（同一顆棋子被兩段程式碼各畫一次）
- 動畫時間抽成共用常數 `constants.js`（原本 260ms / 280ms 分散在兩個檔案，改一邊忘另一邊就會不同步）
- 清掉全部 lint 警告

## 已知問題修正紀錄（相對前一版 3D 原型）
- 修正：AI 走子時棋子憑空消失、畫面沒有更新的問題 → 現在玩家與 AI 走子共用 `executeMove`，保證動畫與狀態更新同步執行
- 修正：棋盤在畫面裡被裁切、需要拖到角落才看得到的問題 → 改用 2D 等角座標計算，動態算出棋盤四個角落座標決定容器尺寸，確保完整棋盤永遠置中顯示

## 部署到 GitHub Pages
1. 把這個資料夾 push 到你的 GitHub repo
2. 到 repo 的 Settings → Pages → Source 選擇 "GitHub Actions"
3. 每次 push 到 main 分支會自動建置並部署（見 \`.github/workflows/deploy.yml\`）
4. 如果你的 repo 名稱不是 \`chess-game\`，記得把 \`vite.config.js\` 裡的 \`base\` 改成你的 repo 名稱，例如 repo 叫 \`my-chess\`，就改成 \`base: '/my-chess/'\`
